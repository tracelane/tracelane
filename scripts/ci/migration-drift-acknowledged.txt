# Format:  kind|name|column|REASON
# A line with an empty REASON is REFUSED, not honoured — an override without a record
# is not a control. `PENDING <YYYY-MM-DD>` expires on that date and the gate
# fires again, so a deferral cannot quietly become permanent.
#
# `kind` (B-421, 2026-09-19): `<db>:<direction>:<object>` — db `pg` | `ch`, direction
# `missing` (declared in git, absent live) | `extra` (live, declared nowhere), object
# `table` | `view` | `column` | `index` | `trigger` | `function` | `constraint` | `type`.
# A bare `<object>` (every line written before 2026-09-19) means `pg:missing:<object>`.
# For `column` the name is the TABLE and the third field the column; for a ClickHouse
# `index` the name is `table.index` (skip indexes are per-table). Both tools read this
# file; audit-migration-drift.py ignores the namespaced kinds it does not understand.
#
# WHY MOST OF THIS FILE EXISTS — established against the live Frankfurt catalog
# 2026-08-09 (293 objects). There are TWO migration trees and they target TWO
# databases:
#
#   apps/web/db/migrations/          Drizzle. Built prod Neon. CANONICAL (CLAUDE.md r5).
#   infra/dev/postgres/migrations/   The dev docker-compose Postgres. NOT applied to
#                                    prod — with ONE exception, migration 14, which was
#                                    hand-applied and landed HALF-DONE. That is.
#
# The two trees name the same logical objects differently: dev uses `idx_<table>_<col>`,
# Drizzle uses `<table>_<col>_idx`. A rename is INVISIBLE to this tool by construction,
# so each one is recorded here by hand with the live object it maps to. Every mapping
# below was checked against the live catalog, not inferred from the name.
# (check-db-drift.py reads ONLY the canonical apps/web tree, so the infra/dev lines
# below are idle for it — they stay for audit-migration-drift.py, which reads both.)
