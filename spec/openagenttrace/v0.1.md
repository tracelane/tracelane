# OpenAgentTrace v0.1

**Status:** Draft | **Version:** 0.1.0 | **Date:** 2026-04-29

---

## Overview

OpenAgentTrace is a semantic convention extension for OTel that describes the
lifecycle of AI agents and their interactions. It is additive to the existing
[OTel GenAI semantic conventions](https://opentelemetry.io/docs/specs/semconv/gen-ai/)
and the [OpenInference specification](https://github.com/Arize-AI/openinference).

Tracelane authors OpenAgentTrace and intends to emit it. Any OTel collector that can receive
OTLP can consume OpenAgentTrace spans without modification.

## Span kinds

### 1. `agent.run`

The top-level span for a single agent invocation. Contains the entire agent lifecycle.

| Attribute | Type | Required | Description |
|-----------|------|----------|-------------|
| `agent.name` | string | ✅ | Agent identifier (e.g. `code-reviewer`) |
| `agent.run_id` | string | ✅ | Unique run identifier (UUID v7) |
| `agent.framework` | string | ✅ | Framework: `anthropic`, `openai-assistants`, `langchain`, `langgraph`, `autogen`, `crewai`, `custom` |
| `agent.model` | string | ✅ | Primary model (e.g. `claude-sonnet-4-6`) |
| `agent.goal` | string | ❌ | Human-readable goal or task description |
| `agent.step_count` | int | ❌ | Total steps taken in the run |
| `agent.budget_tokens` | int | ❌ | Max token budget if set |
| `agent.budget_spent_tokens` | int | ❌ | Actual tokens spent |
| `agent.outcome` | string | ❌ | `success`, `failure`, `timeout`, `budget_exceeded`, `blocked` |

### 2. `agent.step`

A single step within an agent run — one iteration of the plan-execute-observe loop.

| Attribute | Type | Required | Description |
|-----------|------|----------|-------------|
| `agent.step.index` | int | ✅ | 0-indexed step number within the run |
| `agent.step.state` | string | ✅ | State: `planning`, `executing`, `observing`, `reflecting` |
| `agent.step.tools_called` | string[] | ❌ | Tool names called in this step |
| `agent.step.decision` | string | ❌ | `continue`, `complete`, `retry`, `abort` |

### 3. `llm.call`

A single LLM API call. Uses OTel GenAI conventions plus OpenInference extensions.

| Attribute | Type | Required | Description |
|-----------|------|----------|-------------|
| `gen_ai.system` | string | ✅ | Provider: `anthropic`, `openai`, `google` |
| `gen_ai.request.model` | string | ✅ | Requested model ID |
| `gen_ai.response.model` | string | ❌ | Actual model used (may differ from requested) |
| `llm.model_name` | string | ✅ | Model name (OpenInference) |
| `llm.token_count.prompt` | int | ✅ | Input tokens |
| `llm.token_count.completion` | int | ✅ | Output tokens |
| `llm.token_count.total` | int | ❌ | Sum |
| `llm.input_messages` | json | ❌ | Serialized input messages (redacted if PII) |
| `llm.output_messages` | json | ❌ | Serialized output messages |
| `llm.thinking` | string | ❌ | Extended thinking / chain-of-thought content |
| `llm.cache_read_tokens` | int | ❌ | Anthropic cache read tokens |
| `llm.cache_creation_tokens` | int | ❌ | Anthropic cache creation tokens |
| `llm.latency_to_first_token_ms` | int | ❌ | Streaming TTFT |

### 4. `tool.call`

A tool invocation within an agent step.

| Attribute | Type | Required | Description |
|-----------|------|----------|-------------|
| `tool.name` | string | ✅ | Tool/function name |
| `tool.call_id` | string | ✅ | Provider-assigned call ID |
| `tool.input` | json | ✅ | Serialized tool arguments (redacted if PII) |
| `tool.output` | json | ❌ | Tool result (redacted if sensitive) |
| `tool.error` | string | ❌ | Error message if tool failed |
| `tool.duration_ms` | int | ❌ | Execution time |
| `mcp.server_name` | string | ❌ | MCP server name if this is an MCP tool |
| `mcp.server_version` | string | ❌ | MCP server version at call time |

### 5. `mcp.tool_list`

A `tools/list` call to an MCP server. Used for rug-pull detection (PP-PR1).

| Attribute | Type | Required | Description |
|-----------|------|----------|-------------|
| `mcp.server_name` | string | ✅ | MCP server name |
| `mcp.server_version` | string | ✅ | Server version at list time |
| `mcp.tools_count` | int | ✅ | Number of tools returned |
| `mcp.tools_hash` | string | ✅ | SHA256 of the sorted tool names list |
| `tracelane.mcp_rugpull_detected` | bool | ❌ | True if tools changed since last list |

## Tracelane-specific attributes (`tracelane.*`)

These are additive to the OTel and OpenInference conventions.

| Attribute | Type | Description |
|-----------|------|-------------|
| `tracelane.tenant_id` | string | Tenant identifier (from JWT) |
| `tracelane.intervention` | string | `none`, `warn`, `block` |
| `tracelane.aft_ids` | string[] | AFT failure mode IDs that fired |
| `tracelane.pii_redacted` | bool | Whether PII redaction was applied |
| `tracelane.prompt_injection_detected` | bool | Whether prompt injection was detected |
| `tracelane.cost_usd` | float | Estimated provider cost in USD |

## Span hierarchy

```
agent.run (root span)
├── agent.step [index=0, state=planning]
│   └── llm.call
├── agent.step [index=1, state=executing]
│   ├── tool.call [name=bash]
│   └── tool.call [name=read_file]
├── agent.step [index=2, state=observing]
│   ├── mcp.tool_list [server=filesystem]
│   └── llm.call
└── agent.step [index=3, state=reflecting]
    └── llm.call
```

## State machine

```
[start]
  │
  ▼
planning ──────────────────────────────────┐
  │                                        │
  ▼                                        │
executing ◄─────────────────────────────┐  │
  │                                     │  │
  ├── tool calls ──► observing ─────────┘  │
  │                                        │
  ├── llm call ──► reflecting ─────────────┘
  │
  ▼
[complete | failure | timeout | blocked]
```

## Conformance levels

| Level | Requirements |
|-------|-------------|
| **Basic** | `agent.run` span with `agent.name`, `agent.framework`, `agent.model` |
| **Standard** | Basic + `agent.step` spans + `llm.call` spans with token counts |
| **Full** | Standard + `tool.call` spans + `mcp.tool_list` spans + `tracelane.*` attributes |

Tracelane does not yet emit at any OpenAgentTrace conformance level: its SDKs
emit vendor-method span names (`anthropic.messages.create`, `mcp.call_tool`)
rather than the `agent.run` / `agent.step` / `tool.call` kinds this spec requires.
