Two roles use this page: customers signing up at app.tracelane.dev, and
operators self-hosting Tracelane.

## Customer browser flow

1. Visit [app.tracelane.dev/sign-in](https://app.tracelane.dev/sign-in) — the same
   route handles first-time sign-up and returning sign-in.
2. Sign in with WorkOS Connect (Google / Microsoft / SAML).
3. The first sign-in for a domain creates a tenant; subsequent users on the
   same domain join it.
4. Pick a plan (Builder $59 / Team $249 / Business $899 / Enterprise).
5. Generate a tenant API key (`tlane_<base62>`). Copy it once — we hash + store.
6. Drop it in your env as `TRACELANE_API_KEY`.
7. Make a call. The trace shows up at [app.tracelane.dev/traces](https://app.tracelane.dev/traces) within a second.

You're done. Predictive guardrails are observe-first: they flag and record
findings on the trace rather than blocking the request. The dashboard surfaces
what was observed and lets you pin or approve tools; it does not switch a rail
into blocking.

## Operator self-host checklist

Eight steps to running Tracelane on your own infra.

<Steps>

<Step title="Reserve infra">
  - Postgres 17 (Neon, RDS, or self-hosted) — tenant + user metadata
  - ClickHouse 24+ — span/audit hot tier
  - R2 (or S3) — span/audit cold tier
  - L4 GPU pool — optional, only for the roadmap SLM-judge inference tier; not required at V1
  - Outbound network to Sigstore Rekor (`rekor.sigstore.dev`) — for best-effort, opt-in Rekor v2 anchoring of audit batches; universal per-run anchoring is on the roadmap
</Step>

<Step title="Set secrets">
  - `POLAR_ACCESS_TOKEN`, `POLAR_WEBHOOK_SECRET` — billing (Polar.sh)
  - `WORKOS_API_KEY`, `WORKOS_CLIENT_ID`, `WORKOS_WEBHOOK_SECRET` — auth
  - `TRACELANE_BYOK_MASTER_KEY` — provider-key envelope encryption (32 bytes, base64-encoded; AES-256-GCM via `ring`)
  - `TRACELANE_APIKEY_PEPPER` — API-key hashing pepper (release builds refuse to boot without it)
  - `CLICKHOUSE_URL`, `POSTGRES_URL` — datastore endpoints. (The R2 cold tier is
    built but not fed in V1, so its `TRACELANE_R2_*` variables are not required.)
</Step>

<Step title="Apply migrations">
  Drizzle is canonical for the control-plane Postgres schema. Apply it before
  starting the gateway:

  ```bash
  pnpm --filter @tracelanedev/web exec drizzle-kit migrate
  ```

  The gateway does **not** apply migrations at boot.
</Step>

<Step title="Configure WorkOS Connect">
  In the WorkOS dashboard:
  - Add your domain
  - Configure SAML or OAuth providers
  - Set the redirect URI to your dashboard's WorkOS callback — the Next.js app handles the SSO callback, not the gateway
  - Add the webhook URL `https://gateway.<your-domain>/v1/webhooks/workos`
  - Set the webhook events: `organization.created`, `user.created`, `dsync.user.created`
</Step>

<Step title="Configure Polar">
  Tracelane v2 pricing requires six `lookup_key`s. Create each as
  a separate product in the [Polar.sh](https://polar.sh) dashboard, with the
  `lookup_key` set on each product's `product_metadata`:

  | Product | `lookup_key` | Price |
  |---|---|---|
  | Builder plan | `builder_v1` | $59/mo |
  | Team plan | `team_v1` | $249/mo |
  | Business plan | `business_v1` | $899/mo |
  | Enterprise plan | `enterprise_v1` | from $2,999/mo (custom) |
  | Audit add-on | `audit_addon_v1` | $999/mo |
  | Trace overage meter | `overage_v1` | $1.20 per 10K traces (metered) |

  Seats are a per-tier **cap**, not a billable meter — an invite past the cap is
  refused with `403 seat_limit_reached`. There is no extra-seat product to create.

  Then:
  - Create Polar meters with these event names: `tokens_processed`, `audit_anchors`
  - Add the Tracelane webhook URL `https://<your-dashboard-domain>/api/webhooks/polar`
  - Subscribe to events: `subscription.created`, `subscription.updated`, `subscription.active`, `subscription.canceled`, `order.created`, `order.paid`
  - Configure the Polar-hosted customer portal — branding, allowed actions
  - Set `POLAR_ACCESS_TOKEN` (organization access token), `POLAR_WEBHOOK_SECRET`, and `POLAR_EXPECTED_ORGANIZATION_ID` in your env

  for the rationale behind seat caps and capped overage. Retention is NOT
  tier-specific — one window applies to every plan.
</Step>

<Step title="Deploy gateway + ingest">
  ```bash
  cargo build --release --workspace
  ./target/release/gateway   # serves :8080
  ./target/release/ingest    # serves OTLP HTTP :4318 + NATS consumer
  ```
</Step>

<Step title="Deploy dashboard + MCP server">
  ```bash
  pnpm install
  pnpm build
  pnpm --filter @tracelanedev/web start
  ```
  The dashboard is a Next.js app. The MCP server is a separate Node process — run it
  from source (`node apps/mcp/dist/index.js`) for local-only use; `npx @tracelanedev/mcp`
  returns a 404 until a release tag publishes the package.
</Step>

<Step title="Production checklist">
  - Agent-tool safety guards reviewed. They run observe-first — they record findings on the trace and do not block the request.
  - Audit log integrity confirmed (`tlane verify <ledger> --tenant-pubkey <base64>` returns 0). Without the trusted key it exits `INCOMPLETE` by design — the hash chain is checked but signatures and anchors are not. The SHA-256 hash chain and Ed25519 per-tenant signing are live; anchored batches carry a resolved Sigstore Rekor v2 inclusion proof (best-effort, opt-in), with universal per-run anchoring on the roadmap.
  - SBOM published — every tagged release carries a Cosign-signed
    `sbom.cyclonedx.json`, uploaded as a workflow artifact by CI.
  - Sigstore signing verified on **release artifacts** (`cosign verify-blob`
    against the `.cosign.bundle` beside each binary, cosign >= 3.0.6) and on the
    container image (`cosign verify` on the published image digest).
  - `cargo audit` and `pnpm audit` clean on the deployed commit.
  - Backups: ClickHouse → R2, Postgres → daily snapshot.
  - Alerting: error + uptime monitoring wired before GA (tooling being finalized).
</Step>

</Steps>
