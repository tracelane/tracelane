Tracelane is fully self-hostable. The same binary that powers
`gateway.tracelane.dev` runs on a $6/mo Hetzner VPS <!-- pricing-guard: allow $6 infra-cost-not-a-plan-price --> or a
hardened production Docker Compose stack.

## Prerequisites

| Dependency | Version | Purpose |
|---|---|---|
| Rust toolchain | 1.88+ (MSRV; this repo pins 1.95 via `rust-toolchain.toml`) | Build gateway + ingest |
| Node.js | 20+ | Dashboard + MCP server |
| pnpm | 9.15.0 (pinned in `package.json`) | Node package manager |
| Postgres | 17+ (Neon-compatible) | Tenant metadata, API keys, billing |
| ClickHouse | 24.12+ | Span hot tier (365-day TTL) |
| NATS | 2.10+ with JetStream | Ingest queue |

## Quick start — local development only

<Warning>
This section brings up a **local development** stack. It is not a production
topology — see [Production — Docker Compose](#production--docker-compose) below.
</Warning>

The fastest path to a running stack:

```bash
git clone https://github.com/tracelane/tracelane
cd tracelane

# Starts Postgres, ClickHouse, NATS, Grafana on local ports
docker compose -f infra/dev/docker-compose.yml up -d

# Apply migrations
./scripts/apply-migration-pg.sh
```

Then start the services:

```bash
# In three separate terminals:
cargo run -p gateway --release
cargo run -p ingest --release
pnpm --filter @tracelanedev/web dev
```

The gateway listens on `:8080`, dashboard on `:3000`.

## Production — Docker Compose

The production stack is the same compose model as dev, hardened: ClickHouse +
NATS/JetStream + gateway + ingest behind a TLS-terminating reverse proxy.
Postgres is external (Neon or RDS); the dashboard runs on Vercel/Cloudflare.
Start from `infra/self-host/` and `infra/docker/` — the compose files that ship
with this repo. (Tracelane Cloud's own production compose is not published.)

```bash
# On your host, from the repo root of your deployment checkout:
docker compose -f infra/self-host/docker-compose.yml up -d
```

Images are built on-node from source. A published Helm chart and
signed Chainguard/Wolfi image registry are on the roadmap — not yet shipped.

## Environment variables

### Required (production)

| Variable | Description |
|---|---|
| `POSTGRES_URL` | `postgres://user:pass@host:5432/tracelane` — read by the **gateway and ingest** (`PGHOST` + friends also work). Leave it unset and the gateway boots with no control plane: API-key validation falls back to the dev stub. |
| `DATABASE_URL` | The same connection string, read by the **Next.js dashboard** (Drizzle/Neon) and `db/seed.mjs`. Set both — they are separate variables, not aliases. |
| `CLICKHOUSE_URL` | `http://host:8123` |
| `NATS_URL` | `nats://host:4222` |
| `WORKOS_CLIENT_ID` | WorkOS Connect client ID |
| `WORKOS_API_KEY` | WorkOS secret key (tenant/user provisioning) |
| `WORKOS_JWKS_URL` | Defaults to `https://api.workos.com/sso/jwks/{client_id}` |
| `WORKOS_ISSUER` | JWT issuer for validation |
| `WORKOS_WEBHOOK_SECRET` | Webhook HMAC secret (provisions new tenants) |
| `POLAR_ACCESS_TOKEN` | Polar.sh organization access token (billing) |
| `POLAR_WEBHOOK_SECRET` | Polar webhook secret (`polar_whs_…`) |
| `POLAR_EXPECTED_ORGANIZATION_ID` | Polar organization id the webhook secret was issued for |
| `TRACELANE_BYOK_MASTER_KEY` | 32-byte master key for BYOK envelope encryption, **base64-encoded** (AES-256-GCM). Not hex — the value is base64-decoded and must yield exactly 32 bytes, so a 64-character hex string decodes to 48 and the gateway refuses to start. Loaded as key id `0`. |
| `TRACELANE_BYOK_MASTER_KEYS` | Optional key ring for rotation: `<id>:<base64>,<id>:<base64>,…` (ids 0–255). The gateway decrypts under every id it holds and encrypts new rows under `TRACELANE_BYOK_ACTIVE_KEK` (default: the highest id). Rotate with `gateway byok-rotate` — add the new key, make it active, redeploy, re-wrap, then drop the old id. |
| `TRACELANE_REKOR_SIGNING_KEY` | PKCS#8 DER base64 Ed25519 key for audit anchoring |

### Optional

| Variable | Default | Description |
|---|---|---|
| `TRACELANE_SELF_HOST_TIER` | `enterprise` (no cap) | Optional per-minute request cap for a self-hosted gateway (`free` 60 rpm, `builder` 600, `team` 6,000, `business` 60,000, `enterprise` = no cap). Read only in self-host mode. Left unset, a self-hosted gateway has no per-minute cap — you own the compute. Set it to cap your own box. |
| `TRACELANE_PORT` | `8080` | Gateway listen port |
| `TRACELANE_REKOR_URL` | — (unset) | Transparency-log endpoint for audit anchoring. Unset or empty ⇒ batches are signed and persisted locally only, with no outbound POST. There is no default log. |
| `TRACELANE_REKOR_ANCHOR_EVERY` | `100` | Audit events per Rekor anchor batch |
| `TRACELANE_BILLING_RETURN_URL` | `/settings/billing` | Polar portal return URL |
| `TRACELANE_METRICS_ADDR` | `127.0.0.1:9465` | Where the gateway serves `/metrics` (Prometheus text). Loopback by default; it is unauthenticated, so publish it only to your scraper. Ingest's exporter is the same variable, default `127.0.0.1:9464` |
| `TRACELANE_MAX_INFLIGHT` | `2048` | Requests allowed in flight at once; the next is refused immediately with `503 overloaded` and `Retry-After: 1` |
| `TRACELANE_REQUEST_TIMEOUT_SECS` | `300` | Ceiling on producing a response head; a streaming body is not under it. Past it the request answers `408 request_timeout` |
| `NEXT_PUBLIC_GATEWAY_URL` | `http://localhost:8080` | Gateway URL shown in dashboard |

<Note>
There are no cold-tier storage variables to set. Cold-tier span archival to
object storage (R2/S3) is not part of the product — spans live in ClickHouse
only.
</Note>

## Apply migrations

```bash
# Postgres — tenant metadata, API keys, CMK keys, billing
./scripts/apply-migration-pg.sh

# ClickHouse — spans, trace_summaries, audit_log (auto-applied by Docker Compose
# from infra/dev/clickhouse/schema.sql at container init).
# Non-compose install — apply schema + migrations directly:
clickhouse-client < infra/dev/clickhouse/schema.sql
for m in infra/dev/clickhouse/migrations/*.sql; do clickhouse-client < "$m"; done
```

<Note>
SLO tables/views (`slo_hourly_stats`, `v_slo_stats`) live in
`infra/dev/clickhouse/migrations/06_genai_attr_keys_and_slo.sql`, **not** in
`schema.sql` — a fresh compose stack must also apply the migrations dir or
`/v1/slo` returns `UNKNOWN_TABLE`.
</Note>

## Configure WorkOS

WorkOS handles SSO (Google, Microsoft, SAML, GitHub, email OTP).

1. Create a WorkOS application at [workos.com](https://workos.com).
2. Set the **Redirect URI** to `https://app.<your-domain>/auth/callback`.
3. Configure **Connections** for the providers you want to support.
4. Add a **Webhook** at `https://gateway.<your-domain>/v1/webhooks/workos`, subscribed to:
   `organization.created`, `user.created`, `dsync.user.created`.
5. Copy the webhook secret to `WORKOS_WEBHOOK_SECRET`.
6. Copy Client ID and API Key to `WORKOS_CLIENT_ID` and `WORKOS_API_KEY`.

## Configure Polar

Tracelane bills through [Polar.sh](https://polar.sh) (Merchant of Record);
there is no direct Stripe integration.

1. Create **Products** with these `lookup_key` values (set on each
   product's `product_metadata`) — monthly and annual are separate Polar
   products:

   | lookup_key (monthly / annual) | Plan | Monthly | Annual (per mo) |
   |---|---|---|---|
   | `builder_v1` / `builder_v1_year` | Builder | $29/mo | $24/mo |
   | `team_v1` / `team_v1_year` | Team | $229/mo | $190/mo |
   | `business_v1` / `business_v1_year` | Business | $799/mo | $665/mo |
   | `enterprise_v1` | Enterprise | from $2,499/mo (custom) | contract |

2. Create six **Meters** with `event_name`:
   - `ingest_gb`, `hot_gb_month`, `series`, `scan_units`, `cold_gb_month`, `eval_runs`

3. Create a **Webhook** at `https://<your-dashboard-domain>/api/webhooks/polar`, subscribed to:
   `subscription.created`, `subscription.updated`, `subscription.active`,
   `subscription.canceled`, `order.created`, `order.paid`.

4. Issue an **Organization Access Token** with read/write scope for products,
   subscriptions, meter events, and customer-portal sessions.

5. Set `POLAR_ACCESS_TOKEN`, `POLAR_WEBHOOK_SECRET`, and `POLAR_EXPECTED_ORGANIZATION_ID`.

## Generate audit signing key

<Note>
The SHA-256 hash chain and Ed25519 per-tenant signing are live. Anchored
batches carry a resolved Sigstore Rekor v2 inclusion proof (best-effort,
opt-in); universal per-run anchoring is on the roadmap.
</Note>

```bash
# Generate Ed25519 signing key for audit signing + Rekor anchoring
openssl genpkey -algorithm ed25519 -out rekor-signing.pem

# Export as PKCS#8 DER base64
openssl pkcs8 -topk8 -nocrypt -in rekor-signing.pem -outform DER | base64 -w 0
# Paste the output into TRACELANE_REKOR_SIGNING_KEY
```

Store `rekor-signing.pem` in your secrets manager. Losing it means you cannot
anchor new audit batches — existing anchors remain verifiable.

## Production checklist

Before accepting production traffic:

- [ ] `TRACELANE_BYOK_MASTER_KEY` set and rotated (32 random bytes, stored in secrets manager)
- [ ] `TRACELANE_REKOR_SIGNING_KEY` generated and stored
- [ ] WorkOS webhook verified (send a test event, confirm tenant is provisioned)
- [ ] Polar products + meters + webhook configured and verified
- [ ] ClickHouse pointing at production cluster (not dev compose)
- [ ] Postgres pointing at production branch (Neon or RDS)
- [ ] TLS termination at reverse proxy (Caddy, Nginx, or Cloudflare Tunnel)
- [ ] Confirm `POSTGRES_URL` is set — a release build has **no** auth fallback and refuses every API key without it
- [ ] OSV-Scanner + Grype clean on deployed commit
- [ ] Conformance suites green: `pnpm --filter @tracelanedev/audit-verifier test`

## Upgrading

```bash
git pull origin main
cargo build --release --workspace
pnpm install && pnpm build

# Run migrations (idempotent)
./scripts/apply-migration-pg.sh
# ClickHouse schema + migrations (non-compose installs):
clickhouse-client < infra/dev/clickhouse/schema.sql
for m in infra/dev/clickhouse/migrations/*.sql; do clickhouse-client < "$m"; done

# Rolling restart: ingest first, then gateway, then dashboard
```
