Four tables — gateway, observability, evals, trust — built the same way as our
[gateway-overhead benchmark](/benchmarks): every number and every claim is sourced, and a
`—` is not a loss, it's a "we didn't find it," which is not the same thing.

## Method

- **Every competitor cell is a link to a numbered source**, fetched from the vendor's own
  page — docs site, pricing page, or public GitHub repository — on **2026-09-07**. No
  third-party blogs, no re-published "comparison" pages from a fourth party.
- **Every Tracelane cell cites a code path, a public doc** ([`/pricing`](/pricing),
  [`/benchmarks`](/benchmarks)) **or a dated production proof** — never a spec or a
  marketing draft. Behind each is a row in our internal, code-verified feature
  inventory, where a row only reads BUILT once someone has read the source that builds
  it; the feature ids in the footnotes name those rows.
- **A cell marked "Not documented" means we did not find that capability documented on
  the vendor's own site as of the fetch date — it does not mean the vendor lacks it.**
  Vendors change their products continuously; if something below is stale, [open an
  issue](https://github.com/tracelane/tracelane/issues) and we'll fix it.
- **"Yes" for Tracelane always means shipped and either deployed to production or
  reproducible from the public repo** — not planned, not "in the design doc." Where a
  capability is partial or gated by plan, the cell says so and the FAQ or a footnote
  explains the boundary.

## Portkey's provider count

Portkey's homepage says **"1,600+ LLMs."** Its own GitHub repository's `src/providers`
directory, read the same day, lists roughly **75 provider modules** — one module (e.g.
`openrouter`) can route to many models, which partly explains the gap between a provider
count and a model count. But Portkey's own pages are not internally consistent: across
different pages we found **three different figures — 250+, 1,600+, and 3,000+** — for what
should be one number. We're not asserting which is "the" real count; we're reporting that
the vendor's own marketing disagrees with itself. Read their repository yourself before
treating any of the three as ground truth: `github.com/portkey-ai/gateway/tree/main/src/providers`.

For our own "150+ providers" claim: it is deliberately conservative against
`crates/gateway/providers.tsv`, the actual provider adapter table in the repo — count it
yourself.

## Honest gaps

Things competitors publish that we do not have. In rough order of how likely they are to
block a deal on day one:

1. **SOC 2 Type II report (published).** Portkey, Helicone (Team+), Langfuse (Pro+),
   Braintrust (all tiers) and LangSmith (Trust Center) all have or reference a published
   SOC 2. **Not yet.**
2. **Data residency / multi-region.** Langfuse offers US, EU, JP (its own abbreviation); LangSmith offers US
   or EU; Portkey and Helicone offer VPC hosting on Enterprise. Tracelane is single-region
   and residency is not customer-configurable. **Not yet.**
3. **HIPAA / BAA.** Documented by Portkey, Langfuse, Helicone, Braintrust and LangSmith,
   each on their higher tiers. **Not yet.**
4. **SAML SSO, documented as a self-serve feature.** Tracelane authenticates through
   WorkOS, but SAML is not documented as an available feature on any public Tracelane
   page today. **Not yet.**
5. **Contractual SLA / uptime guarantee.** `apps/docs/pricing.mdx` states plainly:
   *"Tracelane does not offer a contractual uptime SLA or service credits."* Langfuse and
   Braintrust document one on their Enterprise tiers. **Not yet.**
6. **Slack / PagerDuty alert integrations, documented.** LangSmith documents webhooks +
   PagerDuty; Langfuse documents Slack/GitHub Actions/webhooks; Helicone documents alerts.
   Tracelane's burn-rate alerts on paid plans are not documented as integrating with a
   specific paging tool. **Not yet.**

None of these are silent gaps — every one is stated as a limit in a public Tracelane doc
(mostly [pricing](/pricing)) rather than only showing up when you ask.
