LiteLLM is a widely-adopted open-source Python proxy, and a reasonable default for a lot of teams. This page is about one specific axis: what the request path is written in, and what you can verify about the artifact you deploy.

Tracelane is a Rust gateway with Trusted Publishing OIDC, Cosign keyless signing, attested build provenance, and a vuln-scanning stack of OSV-Scanner + Grype + Syft.

## How we compare

| Claim | Tracelane | LiteLLM |
|---|---|---|
| Language on request path | Rust (Apache 2.0) | Python (MIT core; `enterprise/` under a separate commercial licence) |
| Supply-chain posture | Cosign keyless + attested build provenance + OSV-Scanner + Grype + Syft | PyPI install with transitive dependency surface |
| Token model | Trusted Publishing OIDC (no long-lived registry tokens) | Registry token model per project policy |
| Vuln scanning | OSV-Scanner + Grype + Syft | Not documented |
| Gateway overhead | Low — no interpreter on the hot path (measured figures publish with the Reliability Benchmark v1.0) | Python interpreter on the hot path |
| BYOK key custody | Envelope encryption, AAD bound to (tenant_id, provider_id) | Keys commonly supplied via proxy config / environment |
| Audit ledger | Tamper-evident hash chain + Merkle + Ed25519 per-tenant signing (live); best-effort Rekor v2 inclusion proof on anchored batches (universal anchoring on the roadmap) | Not documented |
| Inline guardrails | Heuristic rails at the gateway (R1–R8), verdicts written to the ledger | Guardrail hook framework with third-party integrations; no ledgered verdict |
| Self-host complexity | Single-node Docker Compose (ClickHouse-backed) | Docker image or Python venv, plus Redis and Postgres for the stateful proxy |
| Migration tool | `tlane import-litellm` reads litellm_config.yaml | — |

## Migration

```bash
# 1. Translate your LiteLLM config
tlane import-litellm --config ./litellm_config.yaml --output ./tracelane.yaml

# 2. Verify the gateway binary signature (Cosign keyless)
# Use a current cosign release to verify.
cosign verify-blob --certificate-identity-regexp \
  'https://github.com/tracelane/tracelane/.github/workflows/release.yml@.*' \
  --certificate-oidc-issuer 'https://token.actions.githubusercontent.com' \
  --bundle ./tracelane.bundle ./tracelane

# 3. Point your agents at the new gateway endpoint
export OPENAI_BASE_URL=https://gateway.tracelane.dev/v1
```

## FAQ

<AccordionGroup>

<Accordion title="Does Tracelane have feature parity with LiteLLM?">
For the request-path features (multi-provider routing, failover, retry, usage/token tracking, BYOK), yes. Tracelane adds inline predictive guardrails, a tamper-evident audit ledger, and OTel GenAI semconv as its canonical wire format; we found none of the three documented for LiteLLM as of 2026-08-26.
</Accordion>

<Accordion title="Is `tlane import-litellm` a complete migration?">
It translates `litellm_config.yaml` 1:1 for provider routing, failover chains, and BYOK key references. Custom Python hooks in your LiteLLM proxy do not auto-port — you'll rewrite those as Tracelane gateway middleware or as separate services. For most teams the config translation is the only manual step.
</Accordion>

<Accordion title="What is Tracelane's vuln-scanning stack?">
OSV-Scanner (Google) for upstream advisories, Grype (Anchore) for container scanning, and Syft (Anchore) for CycloneDX SBOM generation. Every tagged release ships a Cosign-signed CycloneDX SBOM (`sbom.cyclonedx.json` plus its `.cosign.bundle`) as of `v0.2.3`; the container image ships a signed CycloneDX SBOM as a Cosign attestation, and the repository SBOM is regenerated and signed weekly. See [Security](/security).
</Accordion>

</AccordionGroup>
