Promoting a prompt version from `staging` to `production` is a recorded decision, not
an automated test run. Every promotion writes an attributed, tamper-evident entry to
the promotion ledger — see [Prompt Promotion](/prompt-promotion).

Promotion writes are available on **Team $249/mo and above**.

<Note>
**Tracelane does not run eval assertions against a prompt promotion.** There is no
eval-gate suite, no `tracelane.yaml` gate configuration, no assertion vocabulary and
no eval-authoring API — nothing in Tracelane produces the eval-run records such a gate
would read. A promotion to production is recorded as an attributed **manual override**
carrying the actor and the reason, with `eval_run_id: null`.
</Note>

## What a promotion records

| Field | Value |
|---|---|
| `from_env` / `to_env` | the environments moved between |
| `to_version_id` | the prompt version being promoted |
| `decision` | `manual_override` |
| `eval_run_id` | `null` |
| `notes` | `user override by ACTOR: REASON` — both supplied at promote time |

The decision is appended to the tenant's audit chain as a signed `eval.verdict` event,
so who promoted what, when and why is verifiable after the fact.

## Tracelane's own eval suite

The project's own CI uses an eval framework: 68 pain-point assertions +
10 fault-tolerance chaos evals, run on every push.

<Note>
**These report; they do not block.** The suite is not wired as a blocking
required status check, so a red eval does not automatically refuse a change —
it is surfaced and acted on. Assertions that need a live gateway are reported
as **skipped** in CI, never as a fabricated pass; see the status vocabulary in
`evals/pain-points/INDEX.md`.
</Note>

Run the full suite from a clone of the repo:

```bash
pnpm eval:run --suite=all
```

Valid suite names are `all`, `ft` (fault-tolerance), `gc` (gateway-correctness),
`is` (ingest-schema), `pp` (pain-points), `pir` (PII-redaction) and `pi`
(prompt-injection). An unknown suite name exits `2` rather than quietly running
everything.

This suite is Tracelane's own regression harness. It is not a customer-facing eval
product, and it is not connected to prompt promotion.
