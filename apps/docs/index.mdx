**Approval and proof for AI agents that act on money and customer data.**

Your agents pay, refund and pull customer records. Tracelane holds risky tool calls for a person, binds the approval to that exact call so it is used once, and writes the decision to a signed record that you check offline with the open-source verifier.

- **Hold.** A workspace policy can require a person to approve an MCP tool call. The gateway detects and holds it, and the agent gets a "held" answer. Approval holds are in development and not available on every workspace. See [Approvals](/integrations/approvals).
- **Bind.** The approval is tied to the request it was raised for and is used once, then it expires.
- **Prove.** Approval decisions on the default path are written to the tenant's hash-chained ledger, signed per batch, and `tlane verify` replays them offline. The signed approval record is a **Preview**. Read [the audit ledger](/audit-ledger) for what is and is not chained.

Underneath is a Rust gateway with BYOK routing and OTel capture, backed by ClickHouse. It also records gateway calls and guardrail verdicts in the same tamper-evident ledger. Heuristic checks for the lethal trifecta and prompt injection observe alongside, on every request and on every tier. Tool-definition drift and rug-pull checks compare against a definition you approved from the tools Tracelane has observed on your own traffic. A2A/A2UI drift, browser stuck-loops and argument drift are **roadmap**: those detectors gate on payload fields a `/v1/chat/completions` request does not carry, so they do not fire on LLM traffic today. Gateway-level enforcement is opt-in (observe-first by default), and an ML ensemble is on the roadmap.

## Why Tracelane

<CardGroup cols={2}>
  <Card title="Apache 2.0, full stop" icon="scale-balanced">
    Not GPL-3.0 viral. Not ELv2 SaaS-blocked. Run it however you want.
  </Card>
  <Card title="Caught at the gateway, not after" icon="bolt">
    Tool-definition-drift is flagged inline at the gateway, not
    reconstructed from an incident write-up.
  </Card>
  <Card title="Every claim carries an eval" icon="clipboard-check">
    20 conformance evals — 10 fault-tolerance chaos scenarios, 7 gateway-correctness,
    and one each for ingest-schema, PII-redaction and prompt-injection. They run in
    the canonical repository's CI; in this public mirror they ship as readable
    reference, because six of them assert against fixtures the mirror deliberately
    withholds. Structural assertions run green; behavioral ones report as
    **skipped** without a live gateway rather than as a pass.
  </Card>
  <Card title="Tamper-evident ledger" icon="fingerprint">
    SHA-256 hash chain and Ed25519 per-tenant signing, with byte-identical
    verifiers in Rust + Python + TypeScript. Anchored batches carry a resolved
    Sigstore Rekor v2 inclusion proof (best-effort, opt-in); universal per-run
    anchoring is on the roadmap.
  </Card>
</CardGroup>
