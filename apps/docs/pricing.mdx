## FAQ

<Accordion title="What happens if I exceed my trace quota?">
Soft cap at 100% (you get an alert). Overages bill at $1.20 per 10K traces up to 5× your included quota. At 5× we return HTTP 429 + a Slack alert. No surprise bills.
</Accordion>

<Accordion title="How many people can use one workspace?">
Seats ship at launch. Free and Builder are single-seat. Team includes 10 seats (25 maximum), Business includes 25 (50 maximum), and Enterprise is uncapped. Invite by email from **Settings → Team** — invitations are sent through WorkOS, and each invitee is given a `member` or `viewer` role (owner is a separate explicit grant). The cap is enforced when you invite: accepted memberships and pending invitations both consume a seat, and an invite past the cap is refused with a typed `seat_limit_reached` error. Provider keys are BYOK and workspace-scoped, so every seat shares the workspace's keys.
</Accordion>

<Accordion title="What inline guardrails run on every request?">
Heuristic guardrails run inline at the gateway on every request. **Every
agent-safety rail is free** — on the hosted free tier and in an Apache-2.0
self-host alike:

| Free on every deployment | What it catches |
| --- | --- |
| MCP rug-pull detection | a tool whose definition changes after you approved it |
| Lethal-trifecta taint tracking | untrusted input reaching a tool that can exfiltrate |
| Prompt-injection patterns | injection in prompts, tool descriptions and results |
| Tool-schema validation | malformed or unexpected tool calls |
| Cost ceiling | a request that would exceed the configured spend limit |

Team and above add the data-governance and quality rails: secrets/PII detection
and redaction, output-format policy, system-prompt-leak detection, and
topic/competitor policy.

**How rug-pull detection works in practice:** it compares each request's tool
definition against the one you approved. Tracelane records every tool definition
it sees on your traffic, so approving is one click in **Guardrails → Tool
pinning** — there is nothing to configure and no tool JSON to hand-author. After
that, any change to the tool's name, schema or description is flagged as
definition drift on the next request. Tracelane stores the definition *hash*,
never the tool text. Approving pins a definition; it never grants a tool any
capability, which is a separate owner-only setting.

Each rail can flag or halt the request at the gateway, inline, per the
configured policy — detection is observe-first by default, because a
false-positive block is worse than the failure it prevents.

A multi-model ML ensemble (Llama Prompt Guard 2 ONNX + a fine-tuned classifier)
is on the roadmap to augment the heuristic layer. Browser stuck-loop prediction,
A2A/A2UI catalog conformance and argument-drift detection are also roadmap: the
detectors exist, but they gate on payload fields (`mcp_server_name`,
`tool_name`, `protocol`) that a `/v1/chat/completions` request does not carry, so
they do not fire on LLM traffic today.
</Accordion>

<Accordion title="How does Tracelane compare to LangSmith Engine (launched May 13, 2026)?">
Engine clusters production failures after they happen, then drafts PRs and online evaluators in your LangSmith UI. Tracelane sits one step earlier in the agent lifecycle: inline heuristic guardrails at the gateway (multi-model ML ensemble on the roadmap), tamper-evident promotion record on every deploy, and auto-rollback on objective metrics (cost, latency, error rate, guardrail-fire rate). Engine requires the LangSmith trace surface + LangChain-managed inference keys per LangSmith AI ToS. Tracelane is OTel GenAI semconv-native, BYOK zero markup, Apache 2.0 full stack, self-hostable. See [vs LangSmith Engine](/comparisons/vs-langsmith-engine).
</Accordion>

<Accordion title="What is the Audit SKU and do I need it?">
A tamper-evident record of what your agents actually did. Every gateway-proxied request appends a hash-chained audit entry. Entries are batched (100 by default), each batch gets an RFC 6962 Merkle root, and that root is signed with your workspace's own Ed25519 key — the Merkle root is per batch, not per span. Anchored batches carry a resolved Sigstore Rekor v2 inclusion proof on a best-effort basis, with universal per-run anchoring on the roadmap.

**Scope, stated plainly:** only calls proxied through the Tracelane gateway are chained. Spans sent straight from an SDK or an OTLP exporter are stored and queryable, but they are not part of the chain.

The full ledger exports in the offline-verifier wire format, so you or a third party can verify the chain and the signatures independently with `tlane verify --tenant-pubkey` — no Tracelane involvement, no trust in us required. See [Audit Ledger](/audit-ledger).
</Accordion>
